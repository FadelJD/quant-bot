# 02d · Risk layer

Created 2026-11-11 · Wave 2 · Parallel with 02a to 02c, 02e to 02g · Needs 01 · Spec section 11

## Goal

One component with veto power, used identically by the backtester and the live loop. Every limit
is enforced before an order exists. Halts are idempotent.

## Owns

`src/kestrel/risk/`.

## Current state

Sizing, limits and a stateful `RiskEngine` exist. Defects D02, D07.

## Work items

1. **Pipeline as pure functions**, in this fixed order, each returning what it changed:
   clamp negatives (count `clamped_shorts`) → size (`fixed_fraction` or `vol_target`) → cap per
   symbol → scale gross pro rata → **no-trade band** → convert to delta orders → lot rounding →
   minimum notional drop → `max_orders_per_bar` (drop the smallest).
2. **I9 no-trade band (fixes D02).** Skip an adjustment when `|target_w - current_w| <
   risk.rebalance_band` (default 0.02) unless the target is 0 (full exits always go) or the current
   weight is 0 (entries always go). Expected effect on the synthetic quickstart: trade count falls
   from about 3 600 to a few hundred. Record before and after in the handoff note.
3. **Sizing.**
   - `fixed_fraction`: weights as given, scaled so the gross is at most `max_gross_exposure`.
   - `vol_target`: per-symbol weight `(target_vol / n) / vol_i` using 20-bar realised vol, capped
     at `max_weight_per_symbol`, gross capped. Unknown or zero vol falls back to the raw weight
     capped. Document that this ignores correlation (v1 simplification).
4. **State and monitoring (D07).** Rewrite `on_equity` with explicit state:
   `peak_equity`, `sod_equity`, `sod_date`, `last_equity`. Day rollover in UTC by default, with an
   optional market-session rollover for equities. Daily-loss halt lifts on the next day; drawdown
   halt needs an explicit resume. Remove the `hasattr` trick.
5. **Breach objects.** Return a `Breach(kind, reason, ts, until_next_day)` instead of a string, so
   callers do not parse text. Kinds: `daily_loss`, `drawdown`, `adapter_errors`, `manual`.
6. **Serialisable state.** `RiskEngine.state()` and `load_state()` so the live loop restores peak
   and start-of-day equity after a restart instead of re-deriving them from the equity table.
7. **Flatten orders.** `flatten_orders(positions, prices)` returns `risk_exit` sells; calling it
   with no positions returns an empty list. The engine never executes anything itself.
8. **Stale data and adapter errors.** `is_stale(last_bar_ts, now, bar_seconds)` implements "older
   than 2 bar lengths". `on_adapter_error` counts consecutive failures and returns a breach at the
   limit; `on_adapter_ok` resets.
9. **Backtest behaviour.** Keep the two modes decided earlier: `record` (default in backtests:
   breaches become events, trading continues) and `enforce` (flatten and stop, as live does). Move
   the switch into `RiskConfig.backtest_halts` so it is visible in the printed config.
10. **Explainability.** `LimitReport` lists, per symbol, raw target, sized weight, final weight and
    the rule that changed it. The live loop logs it; `kestrel explain-risk` is not needed in v1.

## Done when

- Order of operations is documented in the package docstring and matches the code.
- Trade count on the synthetic quickstart drops by an order of magnitude with the band on.
- Halting twice produces one set of flatten orders.
- `RiskEngine.state()` round-trips through JSON.
- D02, D07 closed. Static checks pass on owned files.

## Out of scope

Executing orders, persisting halt flags (03b), portfolio optimisation, tests.
